n8n en tu propio servidor

1. ¿Conviene hacerlo local?

La edición comunitaria de n8n autoalojada no cobra licencia [3]. El costo está en el servidor que la ejecuta: aquí, tu computadora, y “gratis” no incluye su costo real. Antes de decidir, llena la tabla con tus propias cifras.

LicenciaLa Sustainable Use License es gratuita y aplica solo a la versión autoalojada [3]. Fuentes de terceros indican que puedes dar consultoría y construir workflows para clientes, pero no ofrecerles acceso a tu instancia como servicio de hosting de pago [8]. Esto no es asesoría legal. Ante dudas, escribe a license@n8n.io.

2. Requisitos

  • Windows 10 u 11. Este manual solo se probó en Windows.
  • PowerShell abierto como administrador: clic derecho, “Ejecutar como administrador”.
  • Node.js LTS con npm.
Versión de Node.jsUna copia de la documentación y un tutorial indican que n8n funciona con Node.js 20.19 a 24.x [7][10]. Verifica el rango vigente en docs.n8n.io. La versión probada aquí fue Node.js v24.14.1.
La instalación por npm tiene fecha de caducidadLa documentación oficial indica que las instalaciones con npm quedan obsoletas desde n8n 3.0 [2]. Este manual usa n8n 2.15.1. Para versiones posteriores, revisa las opciones con Docker en la documentación.

3. Instalar

Instala Node.js desde PowerShell:

winget install OpenJS.NodeJS.LTS

Cierra PowerShell y ábrelo de nuevo como administrador. Verifica e instala n8n:

node --version
npm --version
npm install -g n8n
n8n --version

La instalación global con npm install n8n -g y el arranque con n8n start son los comandos de la documentación oficial [2]. Con esta guía, el último comando mostró 2.15.1.

4. Primer arranque

$env:N8N_DIAGNOSTICS_ENABLED='false'
n8n start

Escribe cada comando en su propia línea. Cuando la terminal diga que el editor está accesible, abre http://localhost:5678 en el navegador y sigue el asistente de la primera vez.

Observado en n8n 2.15.1, noviembre de 2026 Al arrancar aparecieron dos avisos: que falta Python 3 para el ejecutor de tareas Python, y que el certificado de licencia no está inicializado. El editor abrió con normalidad. El aviso de Python probablemente solo afecta a nodos Code escritos en Python (inferencia). No confirmé el significado exacto del aviso de licencia.

5. Exponer n8n por HTTPS

Un equipo en casa no recibe llamadas desde internet, y servicios como Telegram exigen una URL HTTPS pública para enviar mensajes a tus workflows [4][5]. Sin ella, n8n arranca bien pero los triggers externos no se activan. La solución es un túnel que dé una URL pública a tu n8n local.

OpciónLo que sabemos
ngrokEs lo que usa esta guía. En el plan gratuito, la URL cambia en cada sesión y hay que repetir la configuración.
Cloudflare TunnelDa un subdominio estable bajo un dominio propio y no abre puertos en tu router [5]. No verificamos costos ni límites.
Túnel integrado de n8nExiste y usa cloudflared, pero requiere Docker [2]. No verificamos si es apto para uso continuo.
VPSYa tiene IP pública, así que no necesita túnel [5], pero tiene costo mensual.

Ejemplo con ngrok

Una sola vez, instala ngrok y autentícalo con el token de tu cuenta:

winget install ngrok.ngrok
ngrok update
ngrok config add-authtoken TU_TOKEN_AQUI

Ventana 1. Abre el túnel y copia la URL que aparece en “Forwarding”:

ngrok http 5678

Ventana 2. Arranca n8n con esa URL:

$env:N8N_DIAGNOSTICS_ENABLED='false'
$env:WEBHOOK_URL='https://xxxx.ngrok-free.dev'
n8n start

La variable WEBHOOK_URL debe ser la dirección HTTPS pública y no localhost; el cambio se aplica reiniciando n8n [4]. Al abrir n8n por túnel puedes ver una página de advertencia de ngrok antes de pasar a n8n; la guía de recuperación indica reiniciar ngrok y repetir la configuración si bloquea las peticiones.

6. Prueba mínima

Antes de construir algo grande, comprueba que el servidor funciona con un workflow de un solo nodo.

  1. En el editor, crea un workflow nuevo y agrega un nodo Webhook. Anota su ruta y su Production URL.
  2. Publica el workflow con el botón Publish.
  3. Abre la Production URL en el navegador, usando la dirección pública del túnel.
  4. Resultado esperado: n8n responde algo y la ejecución aparece en la pestaña Executions.
Verifica en tu versiónLos nombres exactos de los botones y la respuesta por defecto del nodo Webhook pueden variar entre versiones. No los verificamos en la documentación para este manual.

7. Operación y respaldos

Cada vez que reinicias el equipo

  1. Abre ngrok y copia la URL nueva.
  2. Arranca n8n con esa URL en WEBHOOK_URL.
  3. Republica los workflows que usen triggers externos.

Actualizar

npm update -g n8n

Es el comando oficial para actualizar una instalación con npm [2]. Respalda antes de actualizar.

Respaldar

  • Un workflow: menú de tres puntos, Download. Baja un archivo JSON [1].
  • Todos, por consola: n8n export:workflow --all --output=./respaldo/ [6].
  • Credenciales: el comando n8n export:credentials las exporta cifradas, y solo se restauran con la misma clave de cifrado de n8n [6]. Guarda esa clave por separado.

La descarga manual no incluye los valores de las credenciales; al importar en otra instancia tendrás que recrearlas [1][6].

8. Seguridad de secretos

Caso real que motivó este apartadoUn workflow exportado contenía una clave de API completa dentro del encabezado de un nodo HTTP Request. La documentación oficial advierte que estos nodos pueden incluir encabezados de autenticación en el JSON y que hay que quitarlos antes de compartir [1].
  • Antes de compartir o publicar un JSON, búscalo en un editor de texto: Authorization, Bearer, token y key.
  • El JSON también incluye nombres e IDs de credenciales, y los IDs de hojas de Google en los nodos [1].
  • Si una clave llegó a un lugar público o ajeno, revócala y genera una nueva. Borrar el archivo no basta.
  • No pegues claves en documentos, capturas ni repositorios públicos.
  • Si guardas datos personales de usuarios, informa su uso con un aviso de privacidad. Verifica la normativa que aplique en tu país; no la verificamos aquí.

9. Problemas observados

SíntomaQué se observó y qué hacer
Bad request - please check your parameters al activar workflowsApareció al arrancar n8n sin WEBHOOK_URL con un workflow de Telegram publicado. Causa probable: falta la URL HTTPS pública [4]. Define la variable con la URL del túnel y reinicia.
The connection timed out en reintentos de activaciónNo confirmamos la causa. Puede ser red o firewall, o consecuencia del error anterior. Corrige primero la URL pública.
El editor no abre en localhost:5678n8n puede no haber terminado de arrancar. Espera el mensaje “Editor is now accessible” y revisa la terminal.
El comando n8n no se reconoceCierra y vuelve a abrir PowerShell como administrador. Si persiste, repite npm install -g n8n.
Dejó de funcionar tras reiniciar el equipoLa URL de ngrok gratuito cambió. Repite la sección 7.

Lista de verificación final

  1. node --version y n8n --version responden.
  2. El editor abre en localhost:5678.
  3. El túnel muestra una URL HTTPS pública.
  4. n8n arrancó con WEBHOOK_URL igual a esa URL.
  5. La prueba del Webhook responde y deja una ejecución.
  6. Descargaste un respaldo y guardaste la clave de cifrado.
